## 1. Method

The verifier:

1. Parses PARSER_REPORT.md §0 (text between the `## 0.` and `## 1.` headings).
   It walks every Markdown table row, tracks the current `### ` category header
   so each feature knows its family, and extracts every `［＃…］` marker spelled
   inline in that row (handling both 3-column `| ID | name | marker |` tables and
   2-column `| ID | name |` tables).
2. For each feature, derives the marker form(s): strips the `［＃…］` wrapper to
   get the inner marker name, then normalizes by collapsing runs of ASCII /
   fullwidth digits `0-9 / ０-９` and the report's own `Ｎ` placeholder to a
   single `N` token.
3. Checks membership against two canonical sets, both normalized the same way:
   * **chuki_tag.txt** — the first tab-separated column (293 distinct normalized
     rows after de-duplication of the 643 raw rows).
   * **annotation/\*.html** — every `［＃…］` found after HTML tags are stripped
     (326 distinct normalized markers across the 13 spec pages).
   Membership uses exact equality *or* bidirectional substring containment, so
   that e.g. the report's bare `地付き` matches chuki_tag's `ここから地付き` /
   `地付き終わり`, and the manual's `「○○」に傍点` matches chuki_tag's `傍点`.

### Verdict convention (disjoint 5-way partition of feature rows)

| Verdict | Meaning |
|---------|---------|
| `VERIFIED` | marker found in **both** canonical sources |
| `CHUKI-ONLY` | marker found only in chuki_tag.txt |
| `MANUAL-ONLY` | marker found only in annotation/\*.html |
| `UNVERIFIED` | marker in **neither** canonical source (likely report error) |
| `NO-MARKER` | feature row carries no `［＃…］` example to check |

The trust statistic below counts the union (`VERIFIED + CHUKI-ONLY +
MANUAL-ONLY`) as "verified against at least one canonical source", honouring the
literal task wording.

## 5. VERDICT — is §0 trustworthy enough to build a coverage matrix on?

**Not as-is. Use it for the Layout family only; correct L13 and backfill marker
examples for the other six families first.**

Concretely:

* **12 of 13** feature markers verify against canonical sources (**92.3%**) — but
  that denominator is only the Layout family.
* **1 feature** (L13 段組み) is **UNVERIFIED** — a claim corroborated by neither
  source; likely a fabricated or misplaced example.
* **72 of 85 features have no marker example to check** (85%). They cannot be
  mechanically verified at all because §0 lists them name-only. They are not
  *wrong*, but they are *unverifiable*, so a coverage matrix built on §0 today
  would silently inherit any drift in those 72 rows.
* **256 chuki_tag markers and 309 manual markers are absent from §0** as spelled
  examples — i.e. the report's taxonomy covers at most ~13% of the canonical
  marker vocabulary by explicit example.

**Recommendation:** Before standing up a coverage matrix on §0:

1. **Fix L13** — either cite the real source page for `段組み` or drop the row.
2. **Backfill `［＃…］` example columns** for the Headings / Gaiji / Kunten /
   Emphasis / Graphics / Other tables (promote them from 2-col to 3-col), using
   `chuki_tag.txt` + `annotation/*.html` as the source of the example strings.
   This turns the 72 `NO-MARKER` rows into CI-verifiable rows.
3. **Re-run** this verifier in CI (`python3 prototypes/parser-report-verify/verify.py`)
   as a non-blocking drift check so future edits to PARSER_REPORT.md or the
   canonical sources surface immediately.

Once (2) is done, this same script becomes the coverage-matrix gate: every
feature row should be `VERIFIED` (or explicitly `MANUAL-ONLY` for spec features
AozoraEpub3 legitimately omits, like L3 改見開き).
