# Morph pilot report: 98 requested work IDs / 101 AAT files

Date: 2026-04-29

## Scope

This pilot used the existing deterministic `scratch/coverage-pilot-ids.json` sample.
After de-duplicating requested work IDs, the input set contained 98 unique IDs.
`ab-check` emitted 101 AAT JSON files because the corpus index contains multiple records for some IDs.

Pipeline:

```bash
jq 'unique' scratch/coverage-pilot-ids.json > scratch/morph-pilot-100/work-ids.json

cargo run -p ab-check -- \
  --index scratch/ab-index.json \
  --corpus references/aozorabunko \
  --work-ids scratch/morph-pilot-100/work-ids.json \
  --adapter adapters/aozora-rs/target/release/aozora-rs-adapter \
  --output scratch/morph-pilot-100/reports \
  --aat-output scratch/morph-pilot-100/aats \
  --jobs 8

AB_SUDACHI_DICT="$(nix path-info .#sudachi-dictionary-full)/share/sudachi/system.dic" \
  cargo run -p ab-morph-run -- analyze-aat \
  --aat-dir scratch/morph-pilot-100/aats/aozora-rs-adapter \
  --analyzer vibrato \
  --analyzer sudachi-c \
  --analyses-output scratch/morph-pilot-100/analyses.jsonl \
  --comparisons-output scratch/morph-pilot-100/comparisons.jsonl \
  --errors-output scratch/morph-pilot-100/errors.jsonl
```

## Documented report items

### Duplicate text IDs from AAT generation

The comparison output contains duplicate `text_id` rows for:

| text_id | rows |
| --- | ---: |
| `000008_1083` | 2 |
| `000013_542` | 3 |

The duplicate files are emitted by `ab-check` because the corpus index contains multiple records for these IDs, not because morph analysis duplicated work internally. Example files for `000013_542`:

```text
scratch/morph-pilot-100/aats/aozora-rs-adapter/000013_542-f2b43aeff7df.json
scratch/morph-pilot-100/aats/aozora-rs-adapter/000013_542-9dc5cea740ac.json
scratch/morph-pilot-100/aats/aozora-rs-adapter/000013_542-48ba8ab46e27.json
```

Recommended follow-up: preserve the current file-level behavior for now. If corpus-level aggregation needs unique logical works, add an aggregation-layer choice between `text_id` grouping and AAT-file grouping instead of deduping inside `ab-morph-run`.

### Boundary divergence is real signal, not a failure

The lowest boundary-F1 rows have zero coverage mismatches. They represent analyzer segmentation differences, not adapter span bugs. These rows are good candidates for the first ranking/report UI because they have valid evidence and substantial divergence.

## Next recommended loop

Run the same pipeline on a broader deterministic sample, such as 500 unique work IDs. Stop only if:

- `errors.jsonl` is non-empty;
- any comparison has `coverage_mismatch_regions > 0`;
- runtime becomes impractical enough to require batching or parallel analyzer execution;
- duplicate `text_id` handling blocks downstream aggregation semantics.
