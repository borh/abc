# ADR & System Diagrams (Gated Derived Views) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate three maintainable systems diagrams for ABC — an ADR decision map, a system-architecture dataflow graph, and a runtime-provenance graph — as byte-stable Mermaid files regenerated from machine-readable sources and drift-checked, never hand-edited; plus a typed `related` sidecar that carries the semantic ADR relationships headers cannot express.

**Architecture:** Every diagram is a *derived view* over a source of truth, mirroring how the project treats manifests (a diagram is never a competing source of truth). The design is decomplected along two seams the Hickey review surfaced:
1. **Domain vs mechanism.** Each tier splits pure graph construction (`graph-from` — synthetic-testable, no IO) from a thin source-reading `build` wrapper, returning a **graph value** `{:direction :nodes :edges :class-defs}`; lint is likewise `lint-adrs`(pure)/`lint*`(IO). A single deep module `abc.tools.diagram.core` owns all effects — Mermaid rendering + read/compare/write drift-checking — and returns a **result value** `{:ok? :problems :drifts :wrote}` (printing and process exit live only at the `registry/-main` boundary, not in the library). Adding a diagram is a data entry, not new CLI/flake plumbing.
2. **Rendering vs graph.** The graph value is the internal boundary; `abc.tools.diagram.mermaid/flowchart` is one renderer over it (Graphviz / facts-layer renderers stay additive).

Sources of truth, one builder each: ADR headers + a typed `adr-relations.edn` sidecar (Tier 1); `architecture-stages.edn` cross-checked against `schema-contracts.json` (Tier 2); a `workflow-run.json` report (Tier 3, per-run, not committed). The sidecar obeys **single ownership per edge-type**: headers exclusively own `{amends, supersedes, depends-on}`; the sidecar exclusively owns header-inexpressible types `{restates-hard-rule, schema-hash-cascade, harness-for, extends}`; a lint rejects any crossover. ADR 0029 records the whole contract.

**Tech Stack:** Clojure only (`abc.tools.diagram.*`, matching existing tools), `charred` JSON via `abc.tools.json`, EDN sidecars via `clojure.edn`, kaocha tests (`bin/kaocha`), flake `checks` + `clojure -M:abc/validate-design-bundle`. Mermaid as the render target (renders on GitHub + in docs; plain text diffs cleanly). No new runtime dependencies.

## Global Constraints

- **Language:** Clojure only. No Python for the generators (user preference; provenance rendering reuses `abc.tools.json`/charred). Precedents to copy: `src/abc/tools/facts.clj` (emission) and the flake `schema-contract-drift` / `tei-profile-drift` checks (generate-then-byte-diff gate) — reimplemented in Clojure.
- **Determinism:** Every builder MUST yield byte-identical output across runs. `mermaid/flowchart` sorts all nodes/edges/classDefs by a stable key; files end with exactly one trailing newline. This is what makes drift-checking reliable.
- **Derived-view rule:** Committed `.mmd` files are generated. `abc.tools.diagram.core/render` prepends `%% GENERATED by <regen> — do not edit by hand; see ADR 0029`. Never hand-edit them.
- **Single ownership per edge-type:** header fields own `{amends, supersedes, depends-on}`; `adr-relations.edn` owns `{restates-hard-rule, schema-hash-cascade, harness-for, extends}`. Neither layer may declare the other's types (enforced by `adr-graph/lint*`).
- **Tests:** Run with `bin/kaocha` (NOT `clojure -M:test`). Focused: `bin/kaocha --focus <ns-or-test>`.
- **Bundle gate:** `clojure -M:abc/validate-design-bundle` (Clojure alias, not `nix run`, per the git-cliff/nix env gap in project memory).
- **Acceptance gate:** Any ADR with an exact-case `## Acceptance Criteria` heading MUST cite a real `test/…` or `fixtures/…` path (`nix/check-acceptance-criteria.sh`).
- **Formatting:** `cljfmt` must pass on all new `src/`+`test/` files (flake `format` runs `cljfmt check src test`).
- **ADR header format** (`docs/adr/README.md`): header block runs from `# ADR NNNN: Title` to the first `## `; fields `Status:` (single term ∈ {Draft, Proposed, Accepted, Superseded, Withdrawn}), `Supersedes:`, `Amends:`, `Amended by:`, `Depends on:`, `Source:`. ADR refs are written `ADR NNNN`.

```markdown
## Context

The ADR set (0001–0028) and schema bundle encode a real system, but there is
no diagram of it anywhere under `abc/`. Two graphs are latent in the ADRs: an
ADR→ADR decision graph (from `Supersedes`/`Amends`/`Amended by`/`Depends on`
headers) and a system-dataflow graph (artifacts/stages keyed to schemas and
identity coordinates). A runtime provenance graph is additionally available per
executed run from `workflow-run.json`. Critically, the strongest *semantic*
relationships — the Hard-Rule restatement across ADRs 0013–0021, the
schema-hash cascade 0015→0016→0017/0018→0020, the drift harness/model coupling
0021→0020 — live only in README prose today; headers cannot express them.

A hand-drawn diagram, or an untyped overload of `Depends on`, would create a
second silently-drifting source of truth — the failure mode manifest identity
exists to prevent.

## Decision

Diagrams are **generated derived views**, never authored by hand. The pure
domain of each diagram is a **graph value** (`{:direction :nodes :edges
:class-defs}`); Mermaid is one renderer over it. A single module
(`abc.tools.diagram.core`) owns rendering and drift-checking effects over a
registry of committed diagrams.

Three sources of truth, one builder each:

1. **Decision map** — ADR headers unioned with a typed `docs/adr/adr-relations.edn`
   sidecar → `docs/adr/adr-graph.mmd` (`abc.tools.diagram.adr-graph`).
2. **System architecture** — `docs/architecture-stages.edn`, cross-checked
   against `schemas/schema-contracts.json` and the ADR files →
   `docs/architecture.mmd` (`abc.tools.diagram.architecture-graph`).
3. **Runtime provenance** — any `workflow-run.json`, rendered on demand to
   stdout (`abc.tools.diagram.workflow-graph`); per-run, not committed.

Each committed `.mmd` begins with a `%% GENERATED …` header and is byte-stable.
`clojure -M:abc/diagrams --check` regenerates in memory and fails on any
difference; it runs in the flake `diagram-drift` check.

### Typed relationships and single ownership

`adr-relations.edn` is a source of truth (hand-authored, lint-validated — not
generated). To avoid a second home for edges headers already own, ownership is
partitioned by edge-type:

- **Header fields own** `{amends, supersedes, depends-on}`.
- **The sidecar owns** header-inexpressible types
  `{restates-hard-rule, schema-hash-cascade, harness-for, extends}`.

`abc.tools.diagram.adr-graph/lint*` REJECTS any sidecar edge typed as a
header-owned type, any unknown type, any malformed entry, and any `from`/`to`
that does not resolve to an existing ADR. The Tier-1 builder unions both
sources; each edge is styled by type. The sidecar is EDN validated by lint, not
a registered JSON-Schema contract — it is dev-facing documentation metadata,
deliberately kept lower-ceremony than `schemas/schema-contracts.json`.

## Hard Rule

`.mmd` files, `adr-relations.edn`, and `architecture-stages.edn` are
publication/documentation views. They MUST NOT feed `manifest_identity_object`
or change any `artifact_id`, consistent with the global invariant in
`docs/adr/README.md`.

Two ADR-header hygiene rules become binding lints:

- **Reciprocal amend links:** `Amends: ADR B` on A requires `Amended by: ADR A`
  on B.
- **Resolvable references:** every `ADR NNNN` in `Amends:`/`Depends on:` must be
  an existing ADR file.

`Supersedes:` may be scoped prose (e.g. ADR 0012's "TEI stub language in ADR
0006"); the lint does not require a bare `ADR NNNN` there.

## Consequences

- The decision map and architecture diagram cannot silently drift from the
  ADRs/schemas; a stale diagram fails the gate.
- Semantic relationships become first-class, typed, and referentially checked
  instead of prose in the README.
- Adding an ADR, stage, or relation includes regenerating the diagrams (one
  command) and, for amends, backfilling the reciprocal link.
```

```clojure
(ns abc.tools.diagram.mermaid
  "Deterministic Mermaid flowchart renderer. Sorted ordering keeps a regenerated
   diagram byte-stable and safe to commit + drift-check. See ADR 0029."
  (:require [clojure.string :as str]))

(defn sanitize-id [k]
  (str/replace (name k) #"[^A-Za-z0-9_]" "_"))

(defn quote-label [s]
  (str "\"" (str/replace (str s) "\"" "&quot;") "\""))

(defn- edge-arrow [style]
  (case style :dashed " -.->" :thick " ==>" " -->"))

(defn flowchart [{:keys [direction nodes edges class-defs]}]
  (let [dir (or direction "TD")
        node-lines (->> nodes
                        (sort-by (comp sanitize-id :id))
                        (map (fn [{:keys [id label class]}]
                               (str "  " (sanitize-id id) "[" (quote-label label) "]"
                                    (when class (str ":::" (name class)))))))
        edge-lines (->> edges
                        (sort-by (fn [{:keys [from to label]}]
                                   [(sanitize-id from) (sanitize-id to) (str label)]))
                        (map (fn [{:keys [from to label style]}]
                               (str "  " (sanitize-id from) (edge-arrow style)
                                    (when label (str "|" (quote-label label) "|"))
                                    " " (sanitize-id to)))))
        class-lines (->> class-defs
                         (sort-by (comp name key))
                         (map (fn [[k v]] (str "  classDef " (name k) " " v))))]
    (str (str/join "\n" (concat [(str "flowchart " dir)] node-lines edge-lines class-lines))
         "\n")))
```

```clojure
(ns abc.tools.diagram.core
  "Effect-owning driver for committed, drift-checked diagrams. Each diagram is a
   value {:id :out-path :regen :build :lint}; :build is pure (-> flowchart input)
   and :lint is pure (-> problem strings). This module renders and gates them so
   the tier builders stay pure. See ADR 0029."
  (:require [clojure.java.io :as io]
            [abc.tools.diagram.mermaid :as mermaid]))

(defn render [{:keys [regen build]}]
  (str "%% GENERATED by " regen " — do not edit by hand; see ADR 0029\n"
       (mermaid/flowchart (build))))

(defn- drift [{:keys [out-path] :as d}]
  (let [want (render d)
        have (when (.exists (io/file out-path)) (slurp out-path))]
    (when (not= want have)
      (format "DRIFT: %s is stale; run `%s` to regenerate" out-path (:regen d)))))

(defn run!
  "Reconcile committed diagrams with their sources. Reads and (in write mode)
   writes, but does not print or exit — returns a result value the caller
   interprets. Writing is idempotent: identical sources produce identical bytes.
   :ok? is false on any lint problem, or (check mode) any drift."
  [diagrams {:keys [check?]}]
  (let [problems (vec (mapcat (fn [d] ((:lint d))) diagrams))]
    (cond
      (seq problems)
      {:ok? false :problems problems :drifts [] :wrote []}

      check?
      (let [drifts (vec (keep drift diagrams))]
        {:ok? (empty? drifts) :problems [] :drifts drifts :wrote []})

      :else
      {:ok? true :problems [] :drifts []
       :wrote (mapv (fn [{:keys [out-path] :as d}]
                      (spit out-path (render d))
                      out-path)
                    diagrams)})))
```

```clojure
  (->> (str/split-lines content)
       (take-while #(not (str/starts-with? % "## ")))

(defn- adr-refs [s]
  (->> (re-seq #"ADR\s+(\d{4})" (or s ""))
       (map (comp #(Integer/parseInt %) second)) distinct vec))

(defn- field [header field-name]
  (some (fn [l] (when (str/starts-with? l (str field-name ":"))
                  (str/trim (subs l (inc (count field-name))))))
        (str/split-lines header)))

(defn parse-adr [dir filename]
  (let [content (slurp (io/file dir filename))
        header (header-block content)
        title (-> (first (str/split-lines content))
                  (str/replace #"^# ADR \d{4}:" "") str/trim)]
    {:num (adr-number filename) :file filename :title title
     :status (some-> (field header "Status") (str/split #"\s+") first)
     :supersedes (adr-refs (field header "Supersedes"))
     :amends (adr-refs (field header "Amends"))
     :amended-by (adr-refs (field header "Amended by"))

        (format "ADR %04d has non-vocabulary Status %s" (:num a) (pr-str (:status a))))
      (for [a adrs t (concat (:amends a) (:depends-on a)) :when (not (exists? t))]

      (for [a adrs t (:amends a)
            :when (and (exists? t) (not (some #{(:num a)} (:amended-by (by-num t)))))]

              {:id (node-id (:num a))
               :label (format "%04d %s" (:num a) (:title a))
```

```clojure
(ns abc.tools.diagram.workflow-graph
  "Tier 3: render one workflow-run.json as a runtime-provenance DAG. Per-run,
   printed to stdout, not committed. Edges connect a step that produces a target
   key to every step that requires it. See ADR 0029."
  (:require [abc.tools.json :as json]
            [abc.tools.diagram.mermaid :as mermaid]))

(def ^:private status-class
  {"passed" "passed" "failed" "failed" "partial" "partial" "skipped" "skipped"})

(def ^:private class-defs
  {:passed "fill:#1b5e20,stroke:#a5d6a7,color:#fff"
   :failed "fill:#b71c1c,stroke:#ef9a9a,color:#fff"
   :partial "fill:#e65100,stroke:#ffcc80,color:#fff"
   :skipped "fill:#37474f,stroke:#b0bec5,color:#fff"})

(defn run->graph [run]
  (let [steps (get run "steps")
        producers (reduce (fn [m s]
                            (reduce (fn [m k] (update m k (fnil conj #{}) (get s "id")))
                                    m (get s "produces")))
                          {} steps)]
    {:direction "TD"
     :nodes (for [s steps]
              {:id (get s "id")
               :label (str (get s "id") "<br/>[" (get s "status") "]")
               :class (get status-class (get s "status") "skipped")})
     :edges (distinct
             (for [s steps req (get s "requires") p (get producers req)
                   :when (not= p (get s "id"))]
               {:from p :to (get s "id") :label req :style :solid}))
     :class-defs class-defs}))

(defn run->mermaid [run]
  (str "%% GENERATED by clojure -M:abc/workflow-graph <run.json> — per-run; see ADR 0029\n"
       (mermaid/flowchart (run->graph run))))

(defn -main [path & _]
  (when-not path
    (binding [*out* *err*] (println "usage: clojure -M:abc/workflow-graph <workflow-run.json>"))
    (System/exit 2))
  (print (run->mermaid (json/read-json-file path)))
  (flush))
```

```clojure
  "Composition: the committed-diagram registry + CLI entry for `:abc/diagrams`.
   `--check` verifies drift; no arg regenerates. See ADR 0029."
  (:require [abc.tools.diagram.core :as core]

(def committed-diagrams
  [{:id :adr-decision-map :out-path adr/out-path :regen "clojure -M:abc/diagrams"

    :build arch/build :lint arch/lint*}])

(defn -main [& args]
  (let [{:keys [ok? problems drifts wrote]}
        (core/run! committed-diagrams {:check? (boolean (some #{"--check"} args))})]
    (binding [*out* *err*]
      (doseq [p problems] (println "LINT:" p))
      (doseq [d drifts] (println d)))
    (doseq [w wrote] (println "wrote" w))
    (when (and ok? (empty? wrote)) (println "all diagrams current"))
    (System/exit (if ok? 0 1))))
```
